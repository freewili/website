// the hardware

Two boards, every knob and button in use.

Nothing on either board is idle during the demo. The badge's knobs drive the car, its OLED and LEDs show what the tool is doing to it. The Lacerta's coloured buttons, nav pad, touch screen and 16 RGB LEDs all have a job.

T1 CAN-FD Sim badge

the vehicle · lacerta_vehicle

An RP2350B with an MCP251863 CAN FD controller simulates an ECM and a TCM. A vehicle model turns four knob values into load, MAF, MAP, timing, fuel trims, O2 voltages, gear, odometer and readiness monitors.

  • K1 turnEngine speed request, 50 rpm per detent above idle
  • K2 turn / pressVehicle speed · press flips the OLED page (DASH, DIAG, BUS)
  • K3 turn / pressCoolant temperature · press injects the next fault scenario
  • K4 turn / pressThrottle, 2 % per detent · press starts or stops the engine
  • LED 1Request received
  • LED 2Answer sent, negative answer
  • LED 3MIL, flashing on a misfire, cyan pulse during the EVAP test
  • LED 4Session: green default, cyan extended, magenta unlocked, or the colour the tool commands with UDS 2F
  • OLEDDashboard, diagnostics state, last request and answer per ECU, plus a banner for every tool action

RAD Lacerta

the scan tool · lacerta_tool

A FREE-WILi 2 display-CPU app. The main CPU owns the CAN FD controller; the tool drives it over the OneWili display link and runs ISO-TP itself, so every frame stays visible on its TRACE page.

  • NAV ← →Change page: SCAN, LIVE, DTC, TESTS, UDS, TRACE. Tabs are touch targets too.
  • Coloured rowLabelled per page directly above each button, in the button's colour
  • NAV ↑ ↓ + OKPick and run any of the 20 UDS actions
  • CANCELBack out of an armed CLEAR
  • Hold HOME / PAGELeave the app / About screen (5 s)
  • 16 LEDsRed sweep while scanning, a tachometer bar on LIVE, amber pulse with the MIL on, cyan or magenta for the UDS session, white TX and green RX flashes

Termination: a bus needs exactly two 120 Ω terminators. The badge's relay is on by default. With only the two boards, that is enough on a short harness (the badge's bench notes ran it that way). Add Vehicle Spy's ValueCAN with its termination switched on for a properly terminated three-node bus.

// demo walkthrough

Ten minutes, start to finish.

A script that touches every service. Button names refer to the coloured row on the Lacerta, labelled on screen above each button.

  1. Find the vehicle

    On SCAN, press SCAN. A functional 01 00 on 0x7DF brings answers from the ECM and the TCM; the tool reads VIN (with its check digit), calibration IDs, CVNs and ECU names. The 16 LEDs sweep red while it works.

    SCAN01 00 → 7DF09 02 / 04 / 06 / 08 / 0A

  2. Drive it

    Go to LIVE and press RUN. Turn K1 and K2 on the badge: the big tiles, the sparkline and the Lacerta's LED tachometer follow. SINGLE/MULTI switches between one and six PIDs per request.

    RUNSINGLE / MULTIENGINEbadge K1 K2 K3 K4

  3. Break something

    Press K3 on the badge: P0301, cylinder 1 misfire. The OLED shows the fault, RPM turns rough and after three seconds the code is confirmed. LED 3 flashes amber, as a real MIL does for a misfire.

    badge K3 pressP0301 → pending → confirmed

  4. Read the codes

    On DTC, press READ. P0301 shows as confirmed, pending and permanent, with the freeze frame captured when it confirmed. UDS 19 shows the same code as 030100 with status AF (TF, TFTOC, PDTC, CDTC, TFSLC, WIR).

    READUDS 1903 07 0A 02 · 19 02 FF

  5. Clear them, and watch one stay

    Press CLEAR, then CONFIRM. Mode 04 clears the confirmed code, the freeze frame and the MIL, and readiness goes back to incomplete. The permanent code stays until the fault is gone and the car has driven for a while, exactly as J1979 requires.

    CLEARCONFIRM04 → 7DF

  6. Monitors and the EVAP test

    On TESTS, READ shows Mode 06 results with their limits. Inject the catalyst fault and the oxygen-storage test drops below its minimum. Stop the car and press EVAP: Mode 08 seals the system for ten seconds; with the EVAP leak injected it fails and P0442 goes pending.

    READEVAPMODE 0506 · 05 · 08 01

  7. Take control with UDS

    On UDS, press EXTENDED, then UNLOCK: 27 01 returns a seed, the tool computes the key and 27 02 unlocks. LED press sets the badge's LED 4 to a new colour with InputOutputControl; SELFTEST starts a routine that answers "response pending" (NRC 78) before it confirms, while the badge's LEDs run a rainbow.

    EXTENDEDUNLOCKLEDSELFTESTRESET

  8. Write to the car

    From the list, write the idle target (DID 0300) and watch the badge's idle speed change; write the VIN (F190, needs security, a 20-byte multi-frame request); try a wrong key and see NRC 35, then 36, then 37 during the lockout.

    2E 03002E F19027 02 → 7F 27 35

  9. Silence the bus

    Communication control (28 03 01) stops the ECM's periodic messages: in Vehicle Spy, ECM_EngineStatus and ECM_VehicleStatus stop updating and DiagSim_Status shows CommControlTxOff. ControlDTCSetting (85 02) freezes the DTC statuses while a fault is injected.

    28 03 0185 02Vehicle Spy

  10. Lose a module

    Step K3 to scenario 6. The TCM stops answering and broadcasting, the ECM confirms U0101, and the next scan finds a single ECU. Switch on UDS over CAN FD to repeat any UDS read in 64-byte frames.

    badge K3 ×6U0101CAN FD 64
// services

What the simulated ECUs answer.

Requests on 0x7DF reach both ECUs; a request that an ECU cannot serve gets no answer there, as ISO 15765-4 asks. The same request sent physically gets a negative response, which makes the simulator easier to probe.

// on the bus

Watch it in Vehicle Spy.

Import dbc/lacerta_diag_demo.dbc. The periodic messages carry the car's state in engineering units; the diagnostic ids are multiplexed on the service id, so a single frame shows its PID, DID, seed, routine or negative response code by name.

IdMessagePeriodSignals
0C9ECM_EngineStatus20 msEngineSpeed, AccelPedalPosition, EngineLoad, ManifoldPressure, EngineRunning, MIL_On, MIL_Flash, FuelClosedLoop, EngineCold, counter, checksum
1F5TCM_TransStatus50 msGearActual, GearSelector, TransOilTemp, OutputShaftSpeed, TCC_Locked, TCM_MIL_Request, GearRatio, counter, checksum
3E9ECM_VehicleStatus100 msVehicleSpeed, CoolantTemp, IntakeAirTemp, FuelLevel, BatteryVoltage, ConfirmedDTCCount, counter, checksum
3F1ECM_TripData1 sOdometer, EngineRunTime, FuelSystemStatus, counter, checksum
4E0DiagSim_Status500 msSessions, security, DTC setting, comm control, IO control, TCM offline, self test, EVAP test, fault scenario, request and NRC counters
7DFOBD_Functional_Req–PCI type, length, service id and its parameter
7E0 / 7E1ECM_ / TCM_Diag_Req–Multiplexed on the service id: PID, InfoType, session, DID, key, routine, comm control, DTC setting
7E8 / 7E9ECM_ / TCM_Diag_Rsp–Multiplexed on the service id: PID data, DTC counts, P2 / P2*, DID, seed, routine result, rejected service and NRC

Checksums: byte 7 of each periodic message is 0xFF minus the sum of bytes 0–6, and byte 6 carries a 4-bit rolling counter. The DBC is checked in the build against frames produced by the vehicle firmware's own packers (96 decoded values) and parses cleanly in cantools' strict mode.

// build & load

One script for both boards.

Each firmware builds against its own BSP checkout with that BSP's pinned Pico SDK 2.3.0 and ARM GCC 14.2 from ~/.pico-sdk. Nothing needs PICO_SDK_PATH.

# host tests (224 checks), screenshots, DBC check: no hardware
> py -3.12 tools/build.py host

# firmware
> py -3.12 tools/build.py vehicle        # vehicle/build/lacerta_vehicle.uf2
> py -3.12 tools/build.py tool           # tool/build/lacerta_tool.uf2 (SRAM app)

# load
> py -3.12 t1cansimbsp/tools/fw.py backup badge-stock.bin   # once
> py -3.12 tools/build.py flash-vehicle  # 1200-baud touch, BOOTSEL, copy
> py -3.12 tools/build.py install-tool   # to the FW2 SD card's /apps, run from the App Explorer
> py -3.12 tools/build.py ramrun-tool    # or load over the debug probe for a session
