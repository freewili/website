A PolarFire FPGA Orca for FREE-WILi 2.

An idea we would like to build with Microchip. Put a PolarFire FPGA on an Orca module, and FREE-WILi 2 becomes a handheld way to load it, talk to it and debug it — with no programmer pod.

Let's talk → Read the TL;DR
// tl;dr

How it would work as an Orca.

  1. The part. A PolarFire MPF050T or MPF100T on an Orca that snaps onto FREE-WILi 2.
  2. Loading. FREE-WILi 2 programs the FPGA itself over SPI, streaming the Libero design file from its SD card. About 27 seconds, no programmer pod.
  3. Talking to it. After loading, the same SPI wires become a register bus, so scripts and the touchscreen talk straight to the design.
  4. Debug. Registers and a stream FIFO through FREE-WILi 2, its built-in logic analyzer on the header, and a standard JTAG header for SmartDebug.
  5. Building designs. Libero SoC in batch mode behind one command line: lint, simulate, build, load.
  6. First use. A 10BASE-T1S test bench, running beside a SAN DIEGO Orca as the reference.

Status: this is research and a plan. Nothing here has been built or tested on hardware.

// how it works

Three pictures.

// 1: what is on the board

A PolarFire, and what it needs.

The Orca carries the FPGA, three regulators fed from FREE-WILi 2's 5 V, a crystal oscillator, user IO headers and a JTAG header. An ID EEPROM tells the handheld what is plugged in.

The proposed package is the 0.8 mm-pitch FCVG484, which keeps the board buildable on six layers at ordinary PCB fabs.

// 2: one set of wires, two jobs

Load it, then talk to it.

Load: FREE-WILi 2 raises one pin to hand its SPI bus to the PolarFire's programming port, then streams the design file from the SD card. No FlashPro is needed to get a design running.

Run: with that pin low, the same wires reach the fabric. One chip select is a register bus for control and readout; a second is handed to the design untouched as its own SPI port.

The design is stored in the FPGA's flash, so after a reset it is running again in a few milliseconds with no host involved.

// 3: building a design

One command line around Libero.

You write one module; a fixed shell supplies the pins, the register bus and the ID block. A small command-line tool runs Libero SoC in Tcl batch mode for synthesis, place and route, timing and bitstream export.

The same flow is written up for AI coding agents, the way the Orca templates are, so an agent can take a design from an idea to a loaded board.

// first use

A 10BASE-T1S test bench.

The first thing we would do with it: run a 10BASE-T1S core in the PolarFire and test it on a real bus, next to a FREE-WILi 2 with a SAN DIEGO Orca, which uses Microchip's LAN8651.

The Orca would present the same SPI interface as SAN DIEGO, so the T1S screens, counters and test tools FREE-WILi 2 already has work at both ends of the wire.

// design notes

Three things that shape the design.

PolarFire is not a load-on-every-edit FPGA, and the plan is built around that.

  1. Every load is a flash writeThe datasheet allows 1000 programming cycles at 0 to 85 °C. So the flow simulates first, skips a load when the design is already there, and keeps a load counter on the Orca.
  2. Loads take about 27 secondsTypical for both proposed parts. Test controls are therefore registers you change live, not rebuilds.
  3. The tools are LiberoPlace and route and bitstream export are Libero-only, so users need Libero SoC and a licence. Whether the free Silver licence covers the chosen parts is the first thing to confirm.
// the plan

Prove the risky parts first.

Host programming and the batch build flow get proven on a bought development board before any PCB is drawn.

  1. Paper checksLicence coverage, power budget, part choice. Ends in a written go or no-go.
  2. Spike on a dev boardFREE-WILi 2 programs a PolarFire from its SD card. Measure load time.
  3. Orca hardwareRev A board from the Orca template, then the shell, register bus and firmware support.
  4. Open it upA public board-support repository with example designs, documentation and agent guides.
// where microchip can help

Four questions we could not answer alone.

  • Licence coverageDoes the free Libero Silver licence cover MPF050T and MPF100T in the FCVG484 package?
  • Programming codeWhat are the licence terms for SPI-DirectC if parts of it are reused in FREE-WILi 2 firmware?
  • One board, two partsCan one FCVG484 footprint take both MPF050T and MPF100T?
  • A board for the spikeWhich development board best exposes the SPI-slave programming pins for a first test?
